# Secure Vault — Importing from Joplin

Secure Vault imports a **Joplin markdown mirror** — the export layout that
`joplin-mirror` produces — into a vault. The mirror is opened **read-only** and is never
modified. The importer is idempotent: running it twice is a no-op.

Module: `src/vault/importers/joplin_mirror.py`; CLI: `tools/import_joplin.py`.

## 1. Mirror layout (source facts)

Default mirror: `/data/Cloud/Documents/Notes/joplin-mirror`.

```
joplin-mirror/
├── _meta/index.json        authoritative manifest: counts, notebooks, notes, tags, assets,
│                           unresolved_refs
├── assets/                 resource binaries (png/jpg/svg, and a few .md resources)
├── _index.md               generated by the mirror — never imported
├── _meta/ _skills/ __pycache__/ README.md browser.py convert_jex.py
│   joplin_mcp.py open-joplin.bat open-joplin.sh      tooling — skipped by default
└── <notebooks>/<notes>.md  note files with a YAML-ish frontmatter block
```

The manifest is authoritative: `_meta/index.json` lists `notebooks[]`, `notes[]` (with
`id`, `title`, `path`, `tags`, `updated`, `created`, `is_todo`, …), `assets` (a map of
resource id → filename) and `unresolved_refs` (references whose binary is missing).

## 2. Mapping rules

| source | vault |
|---|---|
| notebook `path` | folder at `sanitize(path)` (parents created shallowest-first) |
| note `path` | logical path `sanitize(path)` (the notebook prefix is kept; files are **not** renamed to `title.md`) |
| note body | file content **without** the `--- … ---` frontmatter block |
| `updated` / `created` | file `mtime` / `created` (ISO-8601 → epoch ms, UTC-safe) |
| `tags[]` | tags (verbatim Unicode); `is_todo` adds the tag `todo` |
| `:/<32-hex id>` | `vault:/attachments/<filename>` link (see §3) |
| referenced / all listed assets | files under `attachments/` (level = the note's level) |
| stray `*.md` (not in the manifest, not skipped) | imported as a `normal` note in its folder |

`sanitize()` runs the core path normalizer and replaces `\ : * ? " < > |` and control
characters with `_`, strips trailing dots/spaces per segment and collapses `//`. It keeps
`#`, `$`, `@`, Persian text and emoji.

Sensitivity: `--default-level` (default `normal`) applies to notes and assets. Any note
whose logical path **or** title matches a `--mark-secret GLOB` (fnmatch,
case-insensitive) is imported as `secret`. Globs apply at creation only; the importer
never changes the level of an existing file (it must not lower levels).

## 3. The `vault:/attachments/…` link scheme

Joplin stores inline resources as `:/<32-hex-id>`. The importer imports the binary as
`attachments/<filename>` and rewrites the reference to:

```
![alt](vault:/attachments/<filename>)     # images
vault:/attachments/<filename>             # other references
```

The `vault:` scheme is a deliberate deviation from plain relative markdown links (see
`docs/ARCHITECTURE.md` §5): it is stable when a note is moved between folders. It is
recorded in the importer's kv as `joplin:asset:<resource id>` → `{"path","size","sha256"}`.
A reference whose binary is missing is left untouched and counted in
`report.extra["unresolved_refs"]`; it never fails the run.

## 4. Idempotency

Bookkeeping lives in the metadata `kv` table:

* `joplin:note:<note id>` → `{"path", "updated"}`
* `joplin:asset:<resource id>` → `{"path", "size", "sha256"}`
* `joplin:stray:<relative path>` → `{"path", "size", "sha256"}`

On each run:

* note tracked, `updated` unchanged, file exists → **skip**;
* note tracked, `updated` changed → overwrite the body, keep the level, re-apply tags;
* note untracked → create; if the logical path already exists but is untracked, the
  importer writes `<path> (imported N).md` instead of overwriting (counted in
  `renamed_conflicts`);
* a note removed from the mirror is **never** deleted from the vault.

A dry run counts everything but writes nothing; the second real run is a no-op.

## 5. CLI

```bash
python tools/import_joplin.py \
    --home <vault home> \
    --unlock-file <0600 file with the master password> \
    [--mirror PATH] [--mark-secret GLOB]... [--default-level normal|secret] \
    [--dry-run] [--no-assets] [--no-stray] [--no-skip] \
    [--report PATH] [--json] [--allow-errors] [--seed-example] [--debug]
```

* `--unlock-file` is required and must contain the password (mode `0600`; never argv).
* `--dry-run` writes nothing and prints the counts.
* `--json` prints `report.to_dict()`; otherwise a one-line summary.
* `--report` defaults to `docs/reports/joplin-import-<UTC>.md` (outside the vault home).
* `--seed-example` creates `secrets/EXAMPLE.md` documenting the credential shape.
* Exit code `0` when there are no errors, `1` otherwise (`--allow-errors` forces `0`).
* Refuses to run if the vault home is inside the mirror (`BadRequest`).

Example (scratch vault):

```bash
printf '%s' 'your-master-password' > /tmp/sv.pw && chmod 600 /tmp/sv.pw
./.venv/bin/python tools/import_joplin.py \
    --home /tmp/scratch-vault --unlock-file /tmp/sv.pw --dry-run
./.venv/bin/python tools/import_joplin.py \
    --home /tmp/scratch-vault --unlock-file /tmp/sv.pw \
    --report docs/reports/joplin-real.md
```

There is also a read-only wrapper for the real mirror:
`tools/smoke_import_real.sh --home <scratch> --unlock-file <0600 file> [args…]`.

## 6. KeePass is an explicit non-goal

There is **no** KeePass/kdbx importer and there will not be one (the user's decision in
`docs/DESIGN.md` §14). Passwords belong in `secretfile` files inside the vault, one file
per credential or one note per service. The recommended shape is:

```markdown
# خدمت: <name>

username: <نام کاربری>
password: <گذرواژه>
url: <نشانی سرویس>
notes: <یادداشت>
```

Keep these in a `secrets/` folder and set each entry's level to `secretfile`; the
importer's `--seed-example` flag creates `secrets/EXAMPLE.md` (a `normal` file)
explaining this shape. Never store passwords in `normal` files.
