# SPEC 03 — Qt UI (PySide6): windows, flows, i18n, tray, notifications

Modules: `vault/gui.py` (entry `main()`), `vault/ui/{app,main_window,unlock,new_vault,browser,
editor,viewer,log_panel,search_panel,settings_dialog,tray,notifications,i18n,theme,models}.py`.

The UI is the privileged client: it calls `Service.dispatch(..., role="ui")` **in-process**
(never over the socket) and owns the secret-request flow.

## 1. Entry point & startup sequence

`python -m vault` → `vault.gui:main(argv=None) -> int`.

1. Parse args: `--home PATH`, `--language fa|en`, `--debug`, `--no-tray`, `--self-test`
   (`--self-test` = construct everything offscreen, run the smoke assertions, exit 0 — used by
   the tests, no event loop).
2. `QApplication` with `app.setApplicationName("Secure Vault")`, `setDesktopFileName("secure-vault")`;
   load the bundled font (`assets/Vazirmatn-Regular.ttf` if present, via
   `QFontDatabase.addApplicationFont`) and register it as the default UI font when language is
   `fa`; apply `theme.apply(app, language)` (RTL for fa: `app.setLayoutDirection(Qt.RightToLeft)`).
3. Determine vault home: `--home` → `SECURE_VAULT_HOME` → `ui.json:last_vault_home` →
   `DEFAULT_VAULT_HOME`. If the home has no `.vault-meta.json` → **New Vault wizard**; else →
   **Unlock screen**.
4. After unlock: create `Service`, start the socket server (`socket_server.start(...)` in a
   background thread), build the main window, show the tray icon, start the auto-lock timer
   (1 s tick; uses `session.auto_lock_due()`), and wire `session.on_secret_request` to the
   request dialog.
5. `--no-tray`/headless environments: skip the tray but keep every other behaviour.
6. Single instance: an advisory lock file `runtime_dir()/gui.lock` (fcntl) — a second start
   focuses the running window instead (`QMessageBox` + exit 3). Offscreen/self-test mode skips
   this.

## 2. Screens & flows

### 2.1 Unlock screen (`unlock.py`)
A modal-less main window shown before the vault is unlocked: vault title + path (elided),
a password field (`QLineEdit` with `EchoMode.Password`, focus, Enter submits), a language
switcher (fa/en, top-right), “Open another vault…” (folder chooser), “Create new vault…”,
and a lockout backoff: after 5 failed attempts, wait 5 s × attempts (in-memory only).
Errors show inline in a red label — never a modal for a wrong password. `vault.unlock` returns
`Unauthorized` → message `unlock.wrong_password`.

### 2.2 New-vault wizard (`new_vault.py`)
`QWizard`-less, single dialog with 3 steps in one page: choose folder (default
`DEFAULT_VAULT_HOME`), password + confirmation, and a strength hint (length/entropy label;
no zxcvbn dependency — a simple estimate + a warning if < 10 chars or in a tiny common-password
list bundled in `theme.py`). Optional checkbox “create the recommended folder structure”
(`notes/`, `journal/`, `secrets/`, `attachments/` — created as vault folders).
On success: `VaultSession.create()`, then show the main window. Never log or store the password.

### 2.3 Main window (`main_window.py`)
`QMainWindow` with:
* **Left dock** — the browser (`browser.py`): a folder tree (`QTreeView` + a small
  `QFileSystemModel`-like model over `Index`, `models.py`) + a file list for the selected
  folder, showing an icon/emoji per sensitivity (`🔓 normal`, `🔒 secret`, `🔑 secretfile`) and
  size/mtime columns; a search box above the tree (filename search); toolbar buttons:
  New note, New folder, Import, Refresh, Lock now, Settings.
* **Folder note** — a collapsible panel under the list showing/editing the folder note
  (`vault.set_folder_note`), saved on change with a 1 s debounce.
* **Central area** — the editor (`editor.py`), a `QSplitter`: a `QPlainTextEdit` (markdown
  source) on one side and a preview on the other. Preview = `QWebEngineView` when the module
  imports, else `QTextBrowser` fed by `markdown-it-py` (the venv has it). The preview must be
  **disabled** for `secret`/`secretfile` files.
* **Right dock** — tabs: `log_panel.py` (access log table: time, source, tool, path, outcome,
  with a filter combo + Refresh + “Export CSV”), `search_panel.py` (three separate tabs:
  Filenames / Text / Semantic — each with its own query box, results list; the Semantic tab
  shows a clear “not installed / disabled” state from `semantics.is_available`).
* **Status bar** — lock state (`🔓 unlocked` / `🔒 locked`), vault path, file count, and
  `MCP: <n> connected` (socket server connection count, refreshed each second).
* **Menus/shortcuts** — File (New note `Ctrl+N`, New folder, Import Joplin, Lock `Ctrl+L`,
  Quit `Ctrl+Q`), Edit (Save `Ctrl+S`, Find `Ctrl+F` focuses the search box), View (toggle
  docks, preview on/off), Tools (Settings, Verify integrity, Semantic index now), Help (About,
  “Open log file”).
* **Context menu on a file**: Open, Open in native viewer (secret/secretfile), Rename, Delete,
  Copy path, Set level ▸ (Normal / Confidential / Secret-file) — the level items call
  `vault.set_sensitivity` with role ui (downgrades allowed here, with a confirmation), Tags…
  (`QInputDialog` list editor).
* **Unsaved-changes guard** on switching files/closing (`QMessageBox` Save/Discard/Cancel).

### 2.4 Content opening rules (must match SPEC/01 §9 exactly)
* `normal` → editor + preview immediately.
* `secret` → confirmation dialog first (“This file is marked confidential; open it?”), then
  editor with preview **disabled**, plus a tray notification `notification.secret_opened`.
* `secretfile` → **native viewer only** (`viewer.py`: `QDialog` + read-only `QPlainTextEdit`,
  no markdown rendering, no web engine, with a Copy button and a “copied” notification);
  opening it also requires confirmation and logs an access row with `tool="ui.read_secretfile"`.
* Never load `secret`/`secretfile` content into any web view. Enforce in code, and assert it in
  the UI smoke test (`editor.preview_enabled is False`).

### 2.5 Secret request flow (agent → user)
`session.on_secret_request` fires (from the socket thread → marshal via
`QMetaObject.invokeMethod`/`QTimer.singleShot(0, …)`). The UI shows a non-modal dialog:
“An agent requested to display ‘<path>’ — Show it (native viewer) / Deny”, plus a tray
notification. Show → `viewer.py` dialog + `vault.resolve_open_secret(request_id, approved=True)`;
Deny → `approved=False`. The dialog never auto-closes; it stays until answered. Multiple
pending requests queue (one dialog per request, stacked). All of this is logged.

### 2.6 Tray (`tray.py`)
`QSystemTrayIcon` with the app icon and a menu: Open/Show, Lock now, Search…, Settings…,
Quit. Closing the main window hides to tray (vault stays unlocked) unless “Quit” is chosen;
`Quit` → `session.close()` + tray hide + `app.quit()`. When the vault auto-locks, the main
window returns to the unlock screen and the tray tooltip changes to `locked`.

## 3. i18n (`vault/ui/i18n.py` + `i18n/fa.json`, `i18n/en.json`)

```python
class Translator:
    def __init__(self, lang: str = "fa", i18n_dir: Path | None = None)
    def set_language(self, lang: str) -> None        # emits the `language_changed` callback
    def t(self, key: str, **fmt) -> str              # missing key -> "⟦key⟧" (visible, never a crash)
    @property lang(self) -> str
    def available(self) -> list[str]
def tr(key: str, **fmt) -> str                       # module-level convenience over the current translator
def set_language(lang: str) -> None
def on_language_changed(cb: Callable[[str], None]) -> None
def reload_widgets() -> None                         # re-apply strings to registered widgets
```
* Catalogues are flat JSON objects (`{"unlock.title": "…"}`); **both files must have
  identical key sets** (a test asserts it).
* Every user-visible string in `vault/ui/**` and the tray/notifications goes through `tr(...)`.
  A test greps the UI modules for suspicious literals (Latin/Persian words inside quotes passed
  to `setText`/`setWindowTitle`/`QMessageBox` without `tr(`) and fails on hits.
* Language switching is live: widgets register a refresh callback
  (`i18n.bind(widget, lambda: widget.setText(tr("…")))`) or implement `retranslate()`; the
  main window, docks, dialogs and tray all refresh without a restart, and the layout direction
  flips (`Qt.RightToLeft` for fa).
* Language is persisted in `~/.config/secure-vault/ui.json` (`{"language": "fa", …}`) — it must
  work **before** the vault is unlocked.
* Catalogues must cover at least: unlock screen, new-vault wizard (incl. the password warning),
  menus/toolbar/tooltips, browser columns, editor save states, sensitivity labels & dialogs,
  secret viewer, secret request dialog, search panel (3 kinds + empty states), log panel,
  settings dialog, tray menu, all error messages surfaced from `VaultError.code` values (one
  key per code: `error.VAULT_LOCKED`, `error.PERMISSION_DENIED`, …), and About.

## 4. Settings dialog (`settings_dialog.py`)
* **General**: language (fa/en), vault home (read-only text + “Open folder” button), auto-lock
  minutes (spinbox, 0 = off), “start minimized to tray” (stored in `ui.json`).
* **Vault**: default sensitivity for new files, plain-text threshold (read-only, with an
  explanation — files larger than 10 MB are stored unencrypted by design), verify integrity
  button (runs `vault.verify_blobs`, shows a progress dialog).
* **Semantic search**: enable checkbox, model name, status line from `semantics.is_available`
  (`installed / not installed — install requirements-semantic.txt`), “Build/refresh index” button
  (background thread with a progress dialog, disabled while unavailable), and the number of
  indexed vectors from `vault.stats`.
* **Importer**: Joplin mirror root (default `~/Cloud/Documents/Notes/joplin-mirror`), extra
  sensitive globs, “Run import” button (background thread; shows the report; refuses to run
  while the vault is locked).
* **Log**: path of `daemon.log`, “Open log file”, log level display.
All writes go through `vault.set_settings`; invalid input is rejected with an inline message.

## 5. `vault/ui/models.py`
`VaultTreeModel` (QAbstractItemModel over `Index.walk`, lazy children) and
`VaultListModel` (QAbstractTableModel: name, level icon, size, mtime) with `QSortFilterProxyModel`
for the filename filter. Both must be safe to construct with a locked session (empty) and must
refresh on `session.data_changed` notifications (a tiny callback list on the Service).

## 6. Headless testability requirements (this is what makes P3 verifiable without a screen)

* `QT_QPA_PLATFORM=offscreen` must work for the whole app; no code path may require a real
  display, a notification daemon, or a system tray:
  * tray: wrap in try/except (`QSystemTrayIcon.isSystemTrayAvailable()` false → skip silently);
  * notifications: `notifications.py` uses `QSystemTrayIcon.showMessage` if available, else
    appends to a module-level list (`notifications.recent()`) that the tests assert on;
  * `QWebEngineView` may fail to initialise offscreen → guard with try/except and fall back to
    `QTextBrowser` (and never for secret content anyway).
* `--self-test` mode: builds `MainWindow` against a temporary vault (created+unlocked
  programmatically), exercises the browser/editor/viewer/log/search/settings paths, prints
  `SELFTEST OK` + a summary, and exits without `app.exec()`.
* Assertions the smoke test must be able to make (expose state for them):
  `window.tree_model.rowCount()`, `window.current_path()`, `editor.preview_enabled`,
  `search_panel.last_results(kind)`, `log_panel.row_count()`, `i18n.lang`,
  `app.layoutDirection()`, `viewer.last_text` (module-level for the native viewer dialog).
