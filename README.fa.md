# گاوصندوق امن (Secure Vault)

> زبان دیگر: [English](README.md)

**Secure Vault** یک گاوصندوق رمزشدهٔ شخصی و آفلاین‌محور برای یادداشت **و** رمزهاست. سه رابط روی یک
پوشه است — اپ دسکتاپ Qt (PySide6)، رابط وب محلی در مرورگر، و یک سرور MCP — و **ایجنت‌آگاه** است:
ایجنت ساختار را می‌بیند و یادداشت‌های عادی را می‌خواند، ولی محتوای فایل‌های `secret` و `secretfile`
هرگز به آن داده نمی‌شود و هر دسترسی در یک لاگ فقط‑افزودنی ثبت می‌شود.

جانشین نهایی Joplin است (ایمپورتر، آینهٔ موجود را فقط می‌خواند)، رمزها و کدهای یکبارمصرف را در همان
گاوصندوق نگه می‌دارد، و وابستگی‌هایش عمداً کم است: Python، PySide6، `cryptography`، `argon2-cffi`،
`markdown-it-py` و Pygments.

> **گذرواژهٔ اصلی هرگز ذخیره نمی‌شود و راهی برای بازیابی‌اش نیست.**

**همراهان:** یک [کلاینت اندروید](https://github.com/majidasgari/secure-vault-android) فقط‑خواندنی
(گنجینه) و یک [افزونهٔ فایرفاکس](https://github.com/majidasgari/secure-vault-firefox) از همان
گاوصندوق استفاده می‌کنند — [خانواده](#خانواده--سه-مخزن) را پایین‌تر ببین.

هر سه **یک قالب روی دیسک** را می‌فهمند، پس گوشی و مرورگر *کلاینت* یک گاوصندوق‌اند، نه نسخهٔ دومی از آن.
افزونه با پل حلقهٔ محلی همین برنامه حرف می‌زند ([`docs/BROWSER-AUTOFILL.md`](docs/BROWSER-AUTOFILL.md))
و هر مقداری که بیرون بدهد یک سطر لاگ با `source=browser` می‌گذارد؛ اپ اندروید دقیقاً همان چیدمان پوشه،
`meta.sqlite` و `secure.store` را می‌خواند که این مخزن می‌نویسد.

## این برنامه چیست

Secure Vault یک گاوصندوق رمزشدهٔ شخصی و آفلاین‌محور با رابط گرافیکی Qt (PySide6) است. یادداشت‌ها و
رمزها را به‌صورت بلاب‌های AES-256-GCM در یک پوشه نگه می‌دارد که می‌توانی با هر فضای ابری سینک کنی، یک
ایندکس متادیتای متن‌آشکار (نام‌ها، سطح‌ها، برچسب‌ها، لاگ دسترسی) دارد تا در حالت قفل هم فهرست‌کردن کار
کند، و یک سرور MCP عرضه می‌کند تا ایجنت‌ها ساختار را ببینند و فایل‌های `normal` را بخوانند، در حالی که
محتوای `secret`/`secretfile` پنهان می‌ماند.

## وضعیت

* هسته، API روی سوکت، پل MCP، رابط Qt، رابط وب مرورگری (هم‌تراز با آینهٔ Joplin)، ایمپورتر Joplin،
  ابزار مهاجرت KeePass، پوستهٔ tray، یکپارچه‌سازی دسکتاپ و **سازندهٔ** portable ویندوز پیاده شده‌اند.
* سینک دوطرفهٔ S3 با قفل نوشتن مشارکتی، **بازگردانی از S3** (قبضه‌کردن والتِ داخل باکت —
  `secure-vault-import` روی ماشین بی‌گرافیک) و ریل‌های ایمنی که آینه‌کردن یک والت روی والت دیگر را رد
  می‌کنند (docs/SYNC.md بندهای ۸ و ۹).
* **tray پوستهٔ همیشه‑روشن است**: رابط وب را خودکار و درون‌فرایندی بالا می‌آورد، خواندن
  `secret`/`secretfile` را با دیالوگ «نمایش و کپی» دروازه‌بانی می‌کند، و همیشه نشان می‌دهد همین حالا
  کدام فایل خوانده می‌شود (فید فعالیت + tooltip + SSE). ویرایشگر markdown دسکتاپ به‌ازای هر بلوک
  راست‌چین/چپ‌چین درست است و می‌تواند یادداشت جاری را در مرورگر باز کند.
* رابط گرافیکی **هنوز روی صفحهٔ واقعی آزمایش نشده** — فقط headless/offscreen. فونت، RTL، tray،
  اعلان‌ها و آیکن منوی KDE باید با چشم بررسی شوند.
* **ویندوز پشتیبانی می‌شود**: همان درخت کد روی ویندوز ۱۰+ اجرا می‌شود (دیمن روی endpoint TCP حلقهٔ
  محلی می‌نشیند چون CPython آنجا `AF_UNIX` ندارد، پوشه‌های لاگ/تنظیمات/runtime به
  `%LOCALAPPDATA%`/`%APPDATA%` می‌روند، و گارد تک‌نمونه‌ای رابط گرافیکی یک named mutex است). سوییت
  تست آنجا سبز است و پوشهٔ portables ساخته‌شده با اجرای `--self-test` **داخل خود پوشهٔ ساخته‌شده**
  تأیید شده. `docs/WINDOWS.md` را ببین؛ کارهایی که هنوز آدم لازم دارند در قسمت آخرش فهرست شده‌اند
  (رابط گرافیکی روی صفحهٔ واقعی، امضا، اثر انگشت، یک S3 واقعی).
* سینک پوشه با S3 اختیاری است و بستهٔ اضافه لازم ندارد (boto3 یک بک‌اند جانشین اختیاری در
  `requirements-s3.txt` است): آینه‌سازی دوطرفه با یک فایل قفل مشارکتی، حالت فقط‑خواندنی به‌همراه
  دکمهٔ *گرفتن دسترسی نوشتن*، و دکمهٔ **همگام‌سازی** در اپ دسکتاپ و رابط وب. فقط مختصات غیر‑رمز داخل
  والت می‌ماند؛ کلیدهای دسترسی محلی‑ماشین‌اند. بردارها و کش جای‌گذاری هرگز سینک نمی‌شوند.
* جست‌وجوی معنایی اختیاری است و بستهٔ اضافهٔ `requirements-semantic.txt` را می‌خواهد
  (`sentence-transformers` + ایندکس برداری درون‌ساختی `sqlite-vec`)؛ هیچ‌کدام با `bootstrap.sh`
  نصب نمی‌شوند. بردارها در یک **کش جدا و بازساختنی** زیر خانهٔ کاربر می‌مانند (تنظیمات قابل تغییر) و
  **هرگز سینک نمی‌شوند** (`docs/SYNC.md` را ببین)؛ کش جای‌گذاری محتوا‑محور باعث می‌شود بازسازی فقط
  متنِ ندیده را جای‌گذاری کند. کاربر دانهٔ ریزدانه‌ای را انتخاب می‌کند — کل سند، پاراگراف (پیش‌فرض) یا
  جمله — و می‌تواند دقیقاً انتخاب کند کدام پوشه‌ها داخل بیایند؛ `data:` URI/base64 درون‌خطی پیش از
  جای‌گذاری حذف می‌شود.
* کد یکبارمصرف زنده **فقط درون رابط گرافیکی دسکتاپ** ساخته می‌شود: عمداً هیچ مسیر API، MCP یا وبی
  نمی‌تواند آن را بخواهد.

## نصب

Python ≥ ۳.۱۱ لازم است. روی یک checkout تازه:

```bash
tools/bootstrap.sh
```

این اسکریپت `.venv` را می‌سازد، `.venv/pip.conf` را با آدرس یک آینهٔ PyPI می‌نویسد
(`PIP_INDEX_URL` / `PIP_TRUSTED_HOST` آن را عوض می‌کنند — پیش‌فرض آینه‌ای است که نویسنده به کار
می‌برد)، `requirements.txt` را نصب می‌کند، فونت‌های اختیاری Vazirmatn را دانلود می‌کند (خطا در آن فقط
یک هشدار است) و فرمان‌های بعدی را چاپ می‌کند. idempotent است. با `--skip-deps` وقتی وابستگی‌ها از قبل
نصب‌اند و با `--desktop` برای نصب میان‌بر دسکتاپ.

ویندوز (PowerShell/cmd؛ شرح کامل در `docs/WINDOWS.md`):

```bat
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
bin\secure-vault.cmd
```

## نخستین اجرا

```bash
./bin/secure-vault
```

۱. ویزارد اولین اجرا پوشهٔ گاوصندوق را می‌پرسد (یک پوشهٔ قابل‌دیدن و سینک‌شدنی؛ `SECURE_VAULT_HOME`
   در زمان اجرا آن را عوض می‌کند و انتخاب برای اجرای بعدی می‌ماند) و بعد گذرواژهٔ اصلی.
۲. می‌تواند پوشه‌های توصیه‌شدهٔ سطح بالا را بسازد (`notes/`، `journal/`، `secrets/`، `attachments/`).
۳. **بازیابی گذرواژه وجود ندارد.** اگر گذرواژهٔ اصلی را فراموش کنی، محتوا برای همیشه ناخواندنی است —
   کلید از آن مشتق می‌شود و هیچ‌جا ذخیره نمی‌شود.

بررسی بدون گرافیک (همان که CI و تست‌های این مخزن به کار می‌برند):

```bash
QT_QPA_PLATFORM=offscreen ./bin/secure-vault --self-test
# یا، بدون لانچر:
QT_QPA_PLATFORM=offscreen PYTHONPATH=src ./.venv/bin/python -m vault --self-test
```

## گشت سریع

* **مرورگر** (داک چپ): درختی از پوشه‌ها/فایل‌ها با برچسب سطح حساسیت روی هر ردیف و یک اموجی اختیاری
  ابتدای نام هر پوشه/فایل (ستون `files.emoji`؛ پالت مشترک در `core/emoji.py` است و فهرست دسکتاپ،
  ردیف‌های رابط وب و اپ اندروید همه آن را نشان می‌دهند).
* **ویرایشگر**: متن markdown با پیش‌نمایش برای فایل‌های `normal` (پیش‌فرض خاموش — منوی نما ▸ پیش‌نمایش
  یا دکمهٔ نوارابزار روشنش می‌کند و انتخاب می‌ماند)، قالب‌بندی راست‌چین/چپ‌چین به‌ازای هر بلوک
  (خودکار / RTL / LTR، `Ctrl+Shift+D`) و بلوک‌های کد. برای فایل‌های `secret` پیش‌نمایش غیرفعال است و
  فایل‌های `secretfile` هرگز به ویرایشگر نمی‌رسند. **ویرایش در مرورگر** یادداشت جاری را در رابط وب باز
  می‌کند. هر فایل یک فیلد **یادداشت** یک‌خطی هم دارد که در فهرست فایل‌ها دیده می‌شود.
* **تاریخچهٔ نسخه‌ها**: هر ذخیره بلاب رمزشدهٔ خودش را نگه می‌دارد. دکمهٔ *تاریخچهٔ نسخه‌ها* در
  ویرایشگر همهٔ نسخه‌ها را فهرست می‌کند و دیف رنگی گیت‌مانند بین هر دو نسخه را نشان می‌دهد.
  تاریخچه فقط در رابط کاربری است — ایجنت هرگز نسخه‌های قدیمی را نمی‌خواند.
* **سطح‌های حساسیت**: راست‌کلیک روی فایل → *تعیین سطح* → `normal`، `secret` یا `secretfile`. پایین
  آوردن سطح تأیید می‌خواهد و فقط از رابط کاربری ممکن است.
* **نمایشگر رمز**: یک پنجرهٔ متنی بومی (بدون موتور وب) برای محتوای `secretfile`، تا به رندرکنندهٔ
  markdown نشت نکند. بدنهٔ یک ورودی رمز، دکمه‌هایی می‌گیرد که فیلدهایش می‌طلبند —
  [رمزها و کد یکبارمصرف](#رمزها-و-کد-یکبارمصرف) را ببین.
* **نمایشگر تصویر**: تصاویر در هر سطح حساسیتی در یک نمایشگر بومی باز می‌شوند، هرگز در نمای وب
  (`vault.read_file` می‌تواند با `binary` بایت‌ها را دست‌نخورده برگرداند).
* **جست‌وجو** (داک راست): سه جست‌وجوی جدا — نام فایل‌ها، متن عین (FTS5) و معنایی (اختیاری) — که هرگز
  با هم ترکیب نمی‌شوند.
* **پنل لاگ** (داک راست): لاگ دسترسی فقط‑افزودنی؛ هر فراخوانی ایجنت آنجاست.
* **چیدمان پنجره**: هر چه خودت تنظیم کنی — اندازه/جای پنجره، باز یا بسته بودن داک‌ها و اندازه‌شان، تب
  فعال داک راست، خط‌شکن منبع/پیش‌نمایش و خودِ پیش‌نمایش — در `ui.json` نوشته می‌شود و در اجرای بعدی
  همان‌طور برمی‌گردد (بستن پنجره به tray هم «تنظیم کردن» حساب می‌شود).
* **ظاهر**: سیستمی / تیره / روشن، به‌صورت پالت واقعی Fusion؛ پیش‌نمایش وب و بوم تصویر هم تابع آن‌اند.
* **گشودن سریع با اثر انگشت** (لینوکس، با `fprintd`): می‌توان گذرواژهٔ اصلی را روی صفحهٔ ورود با انگشت
  عوض کرد؛ پشتوانه‌اش یک راز دستگاه محلی است، گذرواژه به‌عنوان راه دوم سر جایش می‌ماند و با خاموش‌کردن
  گزینه، رکورد پاک می‌شود.
* **tray**: پوستهٔ همیشه‑روشن — باز/کپی لینک رابط وب، قفل، آخرین خوانده‌ها (با نشان 🔑 برای خواندن‌های
  محرمانهٔ اخیر)، تنظیمات و خروج. **هیچ فراخوانی ایجنتی بی‌صدا نیست**: هر دسترسی MCP/سوکت — خواندن،
  نوشتن، حذف، جابه‌جایی، فهرست‌کردن پوشه، یا جست‌وجوی نام/متن/معنایی — همان لحظه یک اعلان دسکتاپ با
  عنوان *Agent access (source)* می‌گیرد که عمل و مسیر را می‌گوید (برای جست‌وجو: ابزار و کوئری،
  کوتاه‌شده به ۱۶۰ کاراکتر)، فید فعالیت tray ۲۰۰ رویداد آخر را نگه می‌دارد و tooltip می‌گوید همین حالا
  چه فایلی خوانده می‌شود. خواندن یک فایل `secret` اعلان جداگانه با نام فایل و اینکه کی خواسته می‌گیرد،
  `request_open_secret` ایجنت یک دیالوگ **نمایش و کپی** روی دسکتاپ باز می‌کند، و رویدادهای یکسان در
  ۱٫۵ ثانیه ادغام می‌شوند تا سیل پاپ‌آپ نشود.

## رمزها و کد یکبارمصرف

ورودی‌های رمز زیر پوشهٔ **`رمزها`** می‌مانند — هر ورودی یک فایل، با ساختار
`دسته/<سایت>/<ورودی>.md` (‏`دسته` = category و `سایت` = site)، یک سرتیتر `# عنوان`، یک خط
`سایت: … | دسته: …` و برای هر فیلد یک خط `برچسب: مقدار` (نام کاربری، گذرواژه، آدرس، کد یکبارمصرف).
بدنهٔ این فایل‌ها `secretfile` است: نامشان در ساختار (و در حالت قفل) دیده می‌شود، محتوایشان بدون
گذرواژهٔ اصلی خواندنی نیست، و ایجنت فقط می‌تواند *از تو بخواهد* یکی را نمایش دهی.

باز کردن چنین ورودی‌ای در نمایشگر بومی، بالای متن این‌ها را نشان می‌دهد:

* یک **کارت کد یکبارمصرف** وقتی ورودی کد دارد — یک URI کامل `otpauth://totp/…`، یک بذر لخت base32،
  یا کدی که خودت دستی گذاشته‌ای (کد پشتیبان، همان‌طور که ذخیره شده و هرگز بازتولید نمی‌شود).
  `core/totp.py` استاندارد RFC 6238 است (HMAC-SHA1/256/512)، رقم‌ها برای خواندن با چشم گروه‌بندی
  می‌شوند (۳+۳، ۴+۴، ۳+۳+۳)، و شمارش معکوس با نوار پیشرفت می‌گوید کد بعدی کِی می‌آید؛
* **دکمه‌های رونوشت هر فیلد** — یکی برای کد، یکی برای نام کاربری و یکی برای گذرواژه؛ هر کدام فقط مقدار
  خودش را و بی‌قالب کپی می‌کند. فیلدی که ورودی ندارد دکمه نمی‌گیرد، و هیچ رونوشتی مقدار را در اعلان یا
  سطر لاگ نمی‌گذارد.

`core/totp.py` عمداً پایتون خالص است و **هیچ سطح API یا MCP ندارد**، پس کد زنده را جز آدمِ روبه‌روی
رابط دسکتاپ هیچ‌کس نمی‌تواند بخواهد (خودآزمون `web_views_for_otp = 0` را به‌عنوان گارد رگرسیون
بررسی می‌کند). اپ اندروید و افزونهٔ فایرفاکس کدشان را خودشان، روی همان دستگاه، از مقداری که اجازهٔ
خواندنش را دارند می‌سازند.

## دسترسی ایجنت‌ها (MCP)

پل MCP فایل `bin/secure-vault-mcp` است: یک فرایند stdio بی‌حالت که JSON-RPC را روی سوکت یونیکس محلی با
توکن نقش `mcp` به اپ در حال اجرا می‌فرستد. اپ باید در حال اجرا و باز (unlocked) باشد؛ وگرنه ابزارها
`VAULT_NOT_RUNNING` / `VAULT_LOCKED` برمی‌گردانند.

ثبتش در Hermes (نقشهٔ `mcp_servers`):

```json
{
  "mcp_servers": {
    "secure-vault": {
      "command": "/path/to/secure-vault/bin/secure-vault-mcp",
      "args": [],
      "env": {}
    }
  }
}
```

یا با CLI:

```bash
hermes config set mcp_servers.secure-vault.command "/path/to/secure-vault/bin/secure-vault-mcp"
hermes config set mcp_servers.secure-vault.args "[]"
```

بعضی کلاینت‌ها کلید را `mcpServers` می‌نویسند؛ هرکدام را نسخهٔ Hermes تو می‌خواهد همان را بگذار. برای
عیب‌یابی، `SECURE_VAULT_DEBUG=1` را در محیط سرور بگذار (stdout باید JSON-RPC خالص بماند).

ایجنت چه می‌تواند بکند: فهرست نام‌ها/ساختار، خواندن و نوشتن فایل‌های `normal`، جست‌وجوی نام فایل‌ها و
محتوای فایل‌های `normal` (با `path_prefix` محدودشدنی)، خواندن/نوشتن **یادداشت پوشه و فایل**، گرفتن یک
`digest` یک‌فراخوانی از یک پوشه، فهرست برچسب‌ها (`all_tags`/`files_by_tag`)، خواندن وضعیت جست‌وجوی
معنایی و اجرای `semantic_reindex` محدود به یک شاخه، **بالا بردن** سطح (هرگز پایین آوردن)، گذاشتن
**اموجی** روی پوشه/فایل، و درخواست نمایش یک `secretfile`. چه چیزی را **هرگز** نمی‌تواند: خواندن محتوای
`secret`/`secretfile`، جست‌وجو در آن، پایین آوردن سطح، یا گرفتن محتوای یک `request_open_secret`.
مرجع کامل ابزارها در `docs/MCP.md`.

**هیچ کار ایجنتی سمت تو بی‌صدا نیست.** هر فراخوانی به فید فعالیت tray می‌رسد (۲۰۰ رویداد آخر) و در همان
لحظه یک اعلان دسکتاپ می‌گیرد — *Agent access (mcp)* و بعد عمل و مسیر، یا برای جست‌وجو ابزار و کوئری؛
رویدادهای یکسان در ۱٫۵ ثانیه ادغام می‌شوند. فراخوانی ردشده هم اعلان می‌گیرد، و خواندن یک
`secret`/`secretfile` همیشه اعلان می‌گیرد و همیشه در فید است، هر منبعی که آن را خواسته باشد (فراخوانی‌ای
که با خطا تمام شود در فید می‌ماند ولی پاپ‌آپ نمی‌گیرد).

این مخزن نمونهٔ کوچکی از یک سرور MCP **دوم** روی همان نشست را هم دارد — `tools/max_profile_mcp.py` یک
زیرشاخهٔ گاوصندوق را فقط‑خواندنی سرو می‌کند و خودش هیچ ذخیره‌سازی ندارد — به‌عنوان قالبی برای پل‌های
باریک و هدف‌دار.

## استفاده از مرورگر (رابط وب)

همان گاوصندوق از هر مرورگر روی همان ماشین (یا با اجازهٔ صریح، از شبکهٔ محلی) هم قابل استفاده است.
فرایند وب مالک نشست است؛ کلیدها هرگز از آن خارج نمی‌شوند.

```bash
./bin/secure-vault-web --home /path/to/vault --port 8788
# یا: PYTHONPATH=src ./.venv/bin/python -m vault.web --port 0
```

نشانی و یک **توکن دسترسی** یک‌بار روی stderr چاپ می‌شود. نشانی را باز کن، توکن و گذرواژهٔ اصلی را
بچسبان. هر درخواست `/api/*` باید توکن را در هدر `X-Vault-Token` داشته باشد — کوکی‌ای که لینک
`/?token=…` می‌گذارد عمداً برای مجازکردن یک فراخوانی *کافی نیست*. فارسی‑اول، RTL، واکنش‌گرا تا موبایل و
کاملاً آفلاین (بدون CDN، بدون مرحلهٔ build). SPA همان امکانات مرورگر آینهٔ Joplin را دارد — تم تیره با
کلید روشن، یک جعبهٔ جست‌وجوی کل، درخت پوشهٔ تاشو با شمارش یادداشت هر زیرشاخه، تراشه‌های برچسب،
نماهای پوشه/یادداشت/خام/ویرایش با نوارابزار قالب‌بندی، و سطح هم‌تراز `/api/index` + `/api/search` +
`/api/raw`. برای بایند به یک میزبان غیر‑حلقه‌محلی، `--allow-lan` لازم است. جریان توکن، API و هشدارهای
امنیتی در `docs/WEBUI.md`.

**چاپ** بخشی از نمای یادداشت است: ابتدای پنل یک دکمهٔ **چاپ** دارد (یک `window.print()` بی‌واسطه — نه
اندپوینت خروجی، نه فراخوانی سرور) و یک انتخاب جهت کاغذ. خروجی چاپی فقط خودِ یادداشت است: در
`@media print` پوستهٔ اپ (هدر، درخت پوشه، نوار وضعیت، ردیف دکمه‌ها، مسیر راهنما، تراشه‌های برچسب،
ویرایشگرها و مودال‌ها) حذف می‌شود، صفحه سفید کاغذی با متن تیره می‌شود، خطوط بلند کد می‌شکنند (به‌جای
بریده‌شدن) و جدول‌ها ردیف سرتیترشان را تکرار می‌کنند — بدون این‌ها ته یادداشت بی‌صدا از تا شدن صفحه
بریده می‌شد. جهت کاغذ به‌صورت قاعدهٔ `@page` در خود سند تزریق می‌شود، پس `Ctrl+P` هم همان را رعایت
می‌کند، و انتخاب در `sessionStorage` می‌ماند (`docs/WEBUI.md` بند ۳d).

**معمولاً لازم نیست رابط وب را دستی بالا بیاوری.** اپ Qt پوسته است: بعد از بازکردن قفل، همان
`WebServer` را درون‌فرایندی و روی همان نشست بالا می‌آورد (`web.enabled`، پیش‌فرض روشن) و منوی tray
لینک توکن را باز/کپی می‌کند. اگر نمونهٔ دیگری درگاه/توکن را داشته باشد، این اپ گاوصندوق را قبضه نمی‌کند
و tray را به همان نمونهٔ در حال اجرا اشاره می‌دهد.

## تکمیل خودکار در مرورگر (افزونهٔ فایرفاکس)

گاوصندوق می‌تواند نام کاربری و گذرواژهٔ یک ورودی زیر `رمزها` را به فرم ورود یک سایت بدهد، مثل
افزونه‌های مدیریت رمز — ولی فقط به مرورگری که یک **توکن باریک و جدا** دارد: تنها سطحی که آن توکن باز
می‌کند `/api/autofill/*` است (`vault.browser_status`، `vault.browser_match`، `vault.browser_reveal`)،
هرگز نمی‌تواند `read_file` یا `write_file` صدا بزند، هر مسیری که نام ببرد باید زیر ریشهٔ رمزها باشد،
یک ورودی فقط به **میزبان خودش** تحویل داده می‌شود، و هر reveal یک سطر لاگ با `source=browser` می‌گذارد
(به‌علاوهٔ یک رویداد فعالیت، تا tray نشانش دهد). تطبیق فقط فراداده جواب می‌دهد — هرگز گذرواژه.

کلاینتش افزونهٔ فایرفاکس در
**[secure-vault-firefox](https://github.com/majidasgari/secure-vault-firefox)** است: آیکن را داخل
فیلدها می‌گذارد، با کلیک تو ورودی‌های میزبان همان صفحه را نشان می‌دهد، فقط با کلیک تو پر می‌کند (داخل
یک shadow DOM بسته، تا اسکریپت خود صفحه نتواند برایت کلیک کند)، کد یکبارمصرف را در پاپ‌آپش می‌خواند و
هیچ چیز خودکاری اضافه نمی‌کند. کلید خاموش در اپ دسکتاپ است: **تنظیمات → رابط وب → تکمیل خودکار
مرورگر**. `docs/BROWSER-AUTOFILL.md` قرارداد همین پل است.

## کلاینت اندروید — گنجینه

**[secure-vault-android](https://github.com/majidasgari/secure-vault-android)** کلاینت فقط‑خواندنی
گوشی است، با Kotlin/Compose. `meta.sqlite`، `secure.store` و بلاب‌های `files/<aa>/<blob>.enc` را از یک
prefix باکت می‌گیرد (فقط GET — هرگز PUT و DELETE نمی‌زند و به قفل نوشتن دست نمی‌زند)، کلید را با همان
پارامترهای Argon2id همین اپ مشتق می‌کند و بعد پیمایش، یادداشت پوشه، یادداشت فایل و برچسب‌ها، جست‌وجوی
لفظی با نرمال‌سازی فارسی (نام *همهٔ* فایل‌ها، متن آن‌هایی که روی دستگاه‌اند)، رندر markdown با قاعدهٔ
راست‌چین هر خط، کد یکبارمصرف با رونوشت هر فیلد، گشودن اختیاری با اثر انگشت، و فهرست محلی «اخیراً باز
شده» را عرضه می‌کند. تست‌های واحدش fixtureهایشان را **با خودِ پیاده‌سازی دسکتاپ همین مخزن** می‌سازند
(`tools/make_test_fixture.py`، `tools/make_totp_fixture.py`)، پس هر انحراف در قالب، تست‌هایش را سرخ
می‌کند. عمداً چه نمی‌کند: نوشتن، ویرایش، حذف، تغییر سطح یا برچسب، جست‌وجوی معنایی، تاریخچهٔ نسخه‌ها،
اشتراک‌گذاری، MCP و پنل لاگ دسترسی.

## افزونهٔ فایرفاکس — پر کردن ورود از گاوصندوق

**[secure-vault-firefox](https://github.com/majidasgari/secure-vault-firefox)** همان افزونهٔ MVP است که
در [تکمیل خودکار در مرورگر](#تکمیل-خودکار-در-مرورگر-افزونهٔ-فایرفاکس) توضیح داده شد. یک توکن
محدود به مرورگر از پل حلقهٔ محلی می‌گیرد، خودش هیچ گذرواژه‌ای نگه نمی‌دارد (فقط درگاه و یک توکن
قابل‌ابطال)، بدون کلیک هیچ چیز پر نمی‌کند، و بذر کد یکبارمصرف را حداکثر پنج دقیقه در حافظهٔ صفحهٔ
پس‌زمینه نگه می‌دارد تا شمارش ثانیه به یک خواندن در هر ثانیه از گاوصندوق تبدیل نشود. با گاوصندوقی کار
می‌کند که در همین مخزن اجرا می‌شود — این دو از راه `docs/BROWSER-AUTOFILL.md` با هم نسخه‌بندی می‌شوند.

## ایمپورت

**از Joplin.** ایمپورتر آینهٔ markdown موجود را **فقط‑خواندنی** می‌خواند و داخل یک گاوصندوق می‌نویسد:

```bash
printf '%s' 'your-master-password' > /tmp/sv.pw && chmod 600 /tmp/sv.pw
./.venv/bin/python tools/import_joplin.py \
    --home /tmp/scratch-vault --unlock-file /tmp/sv.pw --dry-run
./.venv/bin/python tools/import_joplin.py \
    --home /tmp/scratch-vault --unlock-file /tmp/sv.pw \
    --report docs/reports/joplin-real.md
```

idempotent است (اجرای دوم هیچ کاری نمی‌کند)، ارجاع‌های منبع `:/<id>` را به لینک‌های
`vault:/attachments/<file>` بازنویسی می‌کند و هرگز به آینه دست نمی‌زند. `docs/IMPORT_JOPLIN.md`.

**از KeePass/Bitwarden.** `tools/keepass-migration/` یک خط لولهٔ «اول طرح، بعد اعمال» است
(`extract.py` → `plan.py`/`curate.py` → `apply.py`، و در پایان `verify.py`) که یک خروجی را به درخت
`رمزها` تبدیل می‌کند: هر ورودی یک `secretfile`، `دسته/<سایت>/<ورودی>.md`، و هیچ مقدار رمزی هرگز از
فایل‌های کاری ۰۶۰۰ بیرون نمی‌زند و به متن ایجنت نمی‌رسد. `apply.py` idempotent است و روی سوکت محلی
کار می‌کند (هر ورودی اول `normal` ساخته می‌شود، بعد به `secretfile` بالا می‌رود، بعد یادداشتش را
می‌گیرد — بالا بردن سطح یادداشت را دور می‌ریزد، پس ترتیب مهم است). بعد `tools/label_folders.py` می‌تواند
یک گاوصندوق زنده را دسته‌ای اموجی‌گذاری کند، بدون کلید اصلی.

## سینک

کل پوشهٔ گاوصندوق را می‌توان با سینک دوطرفهٔ درون‌ساختی به هر باکت سازگار با S3 آینه کرد
(**تنظیمات → سینک S3**؛ بستهٔ اضافه لازم نیست — درخواست‌ها درون‌فرایندی با AWS SigV4 امضا می‌شوند و
`requirements-s3.txt` بک‌اند جانشین اختیاری boto3 را عرضه می‌کند). یک شیء قفل در باکت، طراحی را
تک‑نویسنده می‌کند: اگر دستگاه دیگری قفل را داشته باشد، این نشست **فقط‑خواندنی** باز می‌شود و هر نوشتن
رد می‌شود تا دکمهٔ **گرفتن دسترسی نوشتن** را بزنی؛ قفل با قفل‌کردن/خروج آزاد می‌شود. **همگام‌سازی**
در منوی ابزارهای اپ، tray و هدر رابط وب هست؛ در یک رشتهٔ پس‌زمینه اجرا می‌شود و هر دو رابط پیشرفت زنده
(تعداد آپلود/دانلود) را نشان می‌دهند، پس اپ هرگز هنگ نمی‌کند. **تنظیمات → سینک S3 → آزمون اتصال**
endpoint، باکت و کلیدها را بدون انتقال چیزی بررسی می‌کند. رابط وب بنر فقط‑خواندنی با دکمهٔ گرفتن کنترل
نشان می‌دهد. بردارهای معنایی و کش جای‌گذاری بیرون گاوصندوق‌اند و **هرگز سینک نمی‌شوند**؛ تنظیمات مسیر
کش بردار داخل گاوصندوق را رد می‌کند. می‌توانی پوشه را مثل قبل با Dropbox/OneDrive/Google Drive هم سینک
کنی — هرگز پوشهٔ runtime (`$XDG_RUNTIME_DIR/secure-vault` که `store.*.dec`، سوکت و توکن‌ها را دارد) یا
`semantic.db` را سینک نکن، و دو دیمن را همزمان روی یک پوشهٔ سینک‌شده اجرا نکن. `docs/SYNC.md`.

کلاینت اندروید از همان باکت می‌گیرد (فقط‑خواندنی)، و **بازگردانی از S3** به یک ماشین تازه اجازه می‌دهد
والتِ موجود در باکت را قبضه کند، به‌جای روی‌نویس‌کردنش.

## نکات امنیتی

نام‌ها، اندازه‌ها، زمان‌های تغییر، سطح‌های حساسیت، برچسب‌ها و لاگ دسترسی بدون گذرواژه خواندنی‌اند (در
`meta.sqlite` متن‌آشکار می‌مانند). محتوای فایل‌ها، یادداشت پوشه‌ها، ایندکس FTS و بردارها بدون گذرواژه
هرگز خواندنی نیستند. فایل‌های به‌تمامی بزرگ‌تر از ۱۰ مگابایت **رمزنشده** ذخیره می‌شوند (تصمیم آگاهانهٔ
کاربر)؛ رمزها را در فایل‌های کوچک بگذار. گذرواژهٔ اصلی هرگز ذخیره نمی‌شود. کد یکبارمصرف فقط در رابط
دسکتاپ ساخته می‌شود. مدل تهدید کامل و ماتریس حساسیت در `docs/SECURITY.md` و گسترهٔ دقیق توکن مرورگر در
`docs/BROWSER-AUTOFILL.md`.

## آزمون‌ها

همه آفلاین و با اجراکنندهٔ `unittest` کتابخانهٔ استاندارد اجرا می‌شوند:

```bash
./.venv/bin/python tests/run_tests.py                              # همهٔ سوییت‌ها
./.venv/bin/python tests/run_tests.py --only test_session          # یک سوییت
./.venv/bin/python tests/run_tests.py --only test_web              # سوییت رابط وب
./.venv/bin/python tests/run_tests.py --only test_activity         # فید فعالیت
./.venv/bin/python tests/run_tests.py --only test_bidi             # قواعد جهت ویرایشگر
QT_QPA_PLATFORM=offscreen ./.venv/bin/python tests/test_ui_smoke.py
./.venv/bin/python tools/smoke_e2e.py
./.venv/bin/python tools/smoke_mcp.py
./.venv/bin/python tools/build_windows_portable.py --check         # چاپ CHECK OK
```

روی ویندوز همان فرمان‌ها با `.venv\Scripts\python.exe` اجرا می‌شوند و بیلد portable از داخل پوشهٔ خودش
تأیید می‌شود:

```bat
set PYTHONPATH=
set QT_QPA_PLATFORM=offscreen
cd portable\win && python.exe -m vault --self-test               :: SELFTEST OK
```

سوییت‌های جست‌وجوی معنایی بستهٔ اختیاری را می‌خواهند (`pip install -r requirements-semantic.txt`، یا
حداقل `sqlite-vec` که نصف کوچک آن است)؛ بقیه با همان `requirements.txt` اجرا می‌شوند.

اجرای واقعی روی آینهٔ Joplin اختیاری و فقط‑خواندنی است (`docs/TESTING.md`). دستور گاوصندوق آزمایشی و
فهرست چیزهایی که باید با چشم بررسی شوند در همان فایل است.
